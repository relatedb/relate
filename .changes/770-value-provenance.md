### Added

- Value provenance behind the `RELATE_PREVIEW=value-provenance` preview opt-in (ADR-0610): every commit of an opted-in store retains a transaction record — its metadata map, settable from the CLI's `--tx-meta` flag, `CALL tx.setMetaData`, a Bolt `BEGIN`'s `tx_metadata` extra, the embedded, HTTP, MCP, Python and C channels, or the reserved `@txMetadata` clause annotation (with `RELATE_PREVIEW=cypher-annotations`) — and its derived changed property keys. `provenance(element, key)` answers a property's newest event as `{commitTs, lsn, metadata, value}`, `history(element, key[, maxNum])` its retained timeline, and `CALL db.transactions(since)` audits transactions by metadata with deleted elements included (streamed, a 1024-row cap per call). Records are typed (`type`, default `provenance`), so other machinery can share the family invisibly to the provenance queries.
