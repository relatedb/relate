# Relate executor operator surface — findings for the property-store seam

Repo: /Users/mh/d/rust/relate (read-only main checkout). All paths relative to that root. Established context assumed: `Graph::node_prop_id_at` (relate-executor/src/graph/prop_read.rs:8), token-resolved `node_prop_resolved` (overlay/reads.rs:256), `CompactProps {keys: Vec<u32>, vals: Vec<Value>}` in `LiveNode`, ADR-0614 lazy postings, ADR-0555 row streaming.

## 1. Morsel/batch exchange

**Type the executor exchanges: `Row`, carried clause-to-clause as `Vec<Row>`.**

- `Row` — relate-executor/src/row.rs:116: `pub struct Row { schema: Arc<RowSchema>, values: Vec<Value> }`. Schema (names + HashMap index) is shared per clause batch via `Arc` (`RowNames`, row.rs:54; walk appends via precomputed `RowRung` stamps, row.rs:77/153 — one Arc clone + value pushes per candidate, no per-row name interning).
- Clause boundary: `run_clauses(graph, clauses, params, rows: Vec<Row>, …) -> Result<(Vec<Row>, Option<QueryResult>)>` — relate-executor/src/exec/dispatch.rs:60 (read twin `execute_part_read_seeded`, dispatch.rs:606). So the default inter-clause container is still a whole `Vec<Row>`; ADR-0555 is migrating operators off it.
- The streaming seam that already exists: `pub(crate) enum RowFeed<'a>` — exec/mod.rs:643: `Held(Vec<Row>)` | `Generated(feed::StreamedFeed<'a>)` (pull, one row at a time — UNWIND/LOAD CSV fused generators) | `Folded(Box<aggregate::Aggregation<'a>>)` (push: producer folds rows straight into the consumer's accumulator). `RowFeed::try_for_each(offer)` (mod.rs:671) is the pull loop; `Folded` is the push fold.
- Columnar batch: `Chunk` — exec/chunk.rs:542, with typed `ColumnData` buffers (Int/Float/Utf8/Bool/Value, chunk.rs:130), `NullBitmap`, and derived `ColumnZone` min/max (chunk.rs:103). Used today only inside scan-shaped MATCH clauses by the ADR-0468 batch chain (exec/batch.rs: `compile` gate, `scan_chunk`, `filter_chunk` with selection vector, breaker compacts via `Chunk::retain_rows`/`select_columns`/`to_rows` — `Row` stays the boundary leaving the clause).
- Max batch size: ADR-0555 decision 1 says a batch holds at most 1024 rows, default low hundreds. Enforced per-site by the operators themselves (a code-shape review rule, ADR-0555 decisions 2/5), not by a central type. Concretely: `CHUNK_ROWS: usize = 512` (chunk.rs:39, "the one batch-size knob") and `BATCH_ROWS: usize = 1024` (exec/batch_tail.rs:37, bounds driving rows of the ADR-0641 batched LOAD CSV tail).
- Final result: `QueryResult { columns: Vec<String>, rows: Vec<Vec<Value>>, stats, effect }` — exec/mod.rs:245.

**Verdict: suitable seam target.** `RowFeed` (pull + push) and `Chunk` (columnar, ≤512/1024) are both already defined and already carry the two shapes a property store would want to emit; a store seam should produce `Chunk`-shaped batches or feed `RowFeed::Generated`, not add a third exchange type. (Caveat: `Vec<Row>` remains the default clause boundary — the seam must not assume streaming at every clause hop.)

## 2. Label expansion / candidate production

**One funnel produces candidates, read by both walk engines and the batch chain: `pattern_walk::node_candidates`.**

- Entry: `pub(crate) fn node_candidates(graph, np: &NodePattern, row, params, conjuncts: &[Expr]) -> Result<Vec<NodeId>>` — pattern_walk/candidates/mod.rs:373 (capped twin `node_candidates_capped` mod.rs:420 returning `enum Capped { Within(Vec<NodeId>), Over }`; point ask `point_candidates_capped` mod.rs:456).
- Flow: `funnel` (mod.rs:502) → `binding_arm` (mod.rs:592): classification `Admitted { One, Empty, Scan, Seek }` (mod.rs:539); a named unbound variable runs the seek strategy — every residual conjunct compiled to a `Seek` (candidates/seek.rs:29: `Ids(Vec<NodeId>) | Text | Range | Spatial`), ranked, first served wins via `Seek::serve(&self, graph, labels) -> Option<ServedIds>` (seek.rs:93, `ServedIds::Exact/Superset` seek.rs:188); no seek serves → scan tail `scan_ids` (mod.rs:729) → `graph.lookup_nodes_upto(labels, &props, cap)`, falling through to `graph.all_node_ids()`.
- Storage side of the tail: `ExecGraph::lookup_nodes_upto` (overlay/seek.rs:32) → `Graph::lookup_nodes_upto_at(labels, props, ts, cap)` (graph/index_lookup.rs:123) → `Graph::node_candidates` returns `enum NodeCandidates { Unindexed, Indexed(HashSet<NodeId>), Final(Vec<NodeId>) }` (index_lookup.rs:14); single-label no-prop shape is the canonical label bucket scan `node_ids_with_label_at` (index_lookup.rs:137). Label buckets are `label_index: CoreMap<u32, HashSet<NodeId>>` keyed by interned label id (graph/index.rs:81).
- **Candidates are a materialized, owned `Vec<NodeId>`** (ascending, deduplicated), not a stream or a mask. Every candidate is then re-verified per-row by `node_ok` (exec/candidates/mod.rs:361) through `ReadView` (tombstone-vs-store, mod.rs:442) and the scan predicate gate (predicate_spec.rs `WalkSpec::compile`:341 / `candidate_ok`:518).

**Verdict: suitable seam target, with an adapter.** The "expand label + filter on property" hook belongs exactly at the funnel tail — `scan_ids`/`Graph::node_candidates`/`lookup_nodes_upto_at` — one spelling every consumer already reads (match, GPM, agg folds, batch chain `scan_chunk`, far probe). But the contract returns an owned `Vec<NodeId>`; a columnar store wanting to stream/lazy-evaluate needs either an adapter that materializes, or a new streaming sibling of `lookup_nodes_upto_at` (the `cap` parameter and `RecheckWalk::visit` ControlFlow loop, index_lookup.rs:51-73, already show how a pull form would look).

## 3. Predicate representation and existing pushdown

**Predicates reach the executor as relate-ir `Expr`, and ALL pushdown today is runtime recognition inside the executor — there is no plan→storage pushdown trait.**

- IR: `Expr` (relate-ir; `Expr::Binary { op: BinaryOp, left, right }`, `Expr::seek_value` for row-invariant bounds), `NodePattern { labels, label_expr, properties, prop_keys }` (tokens pre-resolved per ADR-0541). WHERE conjuncts are flattened by `flatten_and_owned` (exec/pushdown.rs:152) and carried as `Residual { conjuncts: &[Expr], scope }` (pushdown.rs:24); readiness/`ready_conjuncts`/`residual_ok_skipping` (pushdown.rs:91/141) evaluate them per row.
- Runtime pushdown recognizers over those Exprs: the `Seek` vocabulary (seek.rs:29 + `leaf_seek` seek.rs:273); the scan predicate gate (`WalkSpec::compile` predicate_spec.rs:341 — property-op-constant conjuncts compiled to inline reads under ONE store read, "settled" so the residual skips them); the batch filter `BatchPred` (exec/batch.rs `compile_pred`, zone-map skips); ADR-0493 range-seek crossover declines.
- **ADR-0614 equality serving — exact signatures** (the closest thing to an existing storage pushdown surface):
  - Executor-facing: `ExecGraph::lookup_nodes(&self, labels: &[String], props: &BTreeMap<String, Value>) -> Option<Vec<NodeId>>` and `ExecGraph::lookup_nodes_upto(&self, labels: &[String], props: &BTreeMap<String, Value>, cap: Option<usize>) -> Option<Vec<NodeId>>` — overlay/seek.rs:18 / :32 (also `lookup_point_upto` overlay/seek.rs:184 for the WHERE `=`/`IN` runtime seek).
  - Base store: `Graph::equality_postings_upto(&self, labels: &[String], props: &BTreeMap<String, Value>, ts: u64, cap: Option<usize>) -> Vec<NodeId>` — graph/index_postings.rs:331; route decided by `Graph::map_equality_route(&self, labels, props) -> EqualityRoute` (index_postings.rs:274) and `values_equality_route` (index_postings.rs:291), where `enum EqualityRoute { Declared, Postings, Scan }` (index_postings.rs:22); decline predicate `equality_postings_serve(labels, values) -> bool` (index_postings.rs:261 — zoned-datetime identity-narrow-than-eq declines); raw bucket read `equality_postings(&self, label: &str, key: &str, value: &Value) -> Vec<NodeId>` (index_postings.rs:228, constraint probes). The serve streams the smallest interned (label,key) identity bucket through the shared `RecheckWalk` re-verification against the snapshot — never materializing the id set when capped.
  - The funnel narrows served answers through the one site `ServedIds::narrowed` (seek.rs:207).

**Verdict: needs adapter.** No plan-level pushdown interface exists to reuse; but the `Seek`/`EqualityRoute`/`equality_postings_upto` vocabulary is exactly the shape a property-store seam should adopt — the seam's "serve equality from the store" method should mirror `lookup_nodes_upto`'s signature (labels, props, cap) and the same decline/narrow semantics.

## 4. Aggregation

**Module: `exec/aggregate/` (grouped path) + `exec/agg_fold/` (folded path); input shape is `RowFeed`.**

- Grouped path: `pub(crate) fn aggregate_ex<'a>(graph, feed: RowFeed<'_>, items: &[Projection], group_by: Option<&[Expr]>, params, subclauses) -> Result<Vec<Row>>` — exec/aggregate/group.rs:390. Internals: `Aggregation::open/offer/finish` (group table `table.rs`, compact key tuple `key.rs`, seed store `seed.rs`, per-group streaming accumulators `stream.rs`/`site.rs`/`columns.rs`, recursive evaluator `eval.rs`, charge `bill.rs`). GROUP BY keys or implicit non-aggregating items; HAVING via `WhereMode` (group.rs:33). count/count(DISTINCT)/collect are aggregate-call sites classified in `site.rs`; collect/percentiles are the declared, charged breakers (ADR-0555 §3).
- Folded/push path: `exec/agg_fold/` (ADR-0036) — `try_fold_one_hop_aggs` / `try_fold_path_aggs` fold a MATCH producer's rows straight into accumulators (`StreamAgg`), so aggregate memory never depends on path count; `RowFeed::Folded(Box<Aggregation>)` hands the half-folded state to the projection (exec/mod.rs:652).
- **Store-side native aggregation already has a precedent seam — the statistics short-circuit ladder**: `stats_short_circuit(ctx, clauses, seed_rows, scope) -> Result<Option<(Vec<Row>, QueryResult)>>` — exec/stats_short_circuit.rs:33, one dispatcher, three rungs tried in order, every decline falls to the clause-loop scan: (1) count-only from maintained stats (exec/count_stats.rs, LABS-370, `CountProbe`), (2) grouped label aggregates from label-set counts (exec/label_set_groups.rs, ADR-0589), (3) grouped/extremum aggregates over one labeled property's index postings — `MATCH (n:L) RETURN n.p, count(*)`, `min/max(n.p)` — exec/index_aggregates.rs (ADR-0611), reading the graph's posting walks `range_extremum_at` / `for_each_posted_value_at` and folding into the shared charged group table. Eligibility gate `stats_view_serves` (stats_short_circuit.rs:28): exact base view, one unbound empty seed row.
- **Verdict: suitable seam target.** A store-side native aggregation over a dictionary column (no row materialization) plugs in as the next rung of `stats_short_circuit` — the dispatcher knows one seam, rungs decline independently, and ADR-0611 already demonstrates value-level (not id-level) store reads feeding the group table. General (seeded, filtered) aggregation over the store would additionally need the `aggregate_ex` offer loop replaced by a store iterator — that part is new engine work, but the rung form covers the whole-population shapes first.

## 5. Sort / limit / top-k

**Operators: `exec/order.rs` (parked-key sort family), `exec/top_k.rs` (bounded window), `exec/match_cap.rs` (MATCH-level limit caps). All operate on `Row`/`Vec<Row>`.**

- ORDER BY: keys are parked as `__ord*` columns at projection time (`OrderKeys`, `park_order_keys`, order.rs:67/81), then `sort_rows_by_parked_keys(rows, keys, top_k: Option<NonZeroUsize>)` (order.rs:415) sorts, or `take_parked_top_k` (order.rs:467) selects. Paging: `page(rows, bounds)` (order.rs:537), `resolve_page_bounds` (order.rs:549), `window_capacity` (order.rs:443).
- Top-k: `TopKWindow` (exec/top_k.rs:57) — the ADR-0555 §3 bounded binary heap an `ORDER BY … LIMIT` folds its producer into row by row (never collects the projection's output); charged as the live window (ADR-0463). Twin for ranked index scans: `TopWindow` (exec/candidates/mod.rs:293, ADR-0256), retaining only `offset + limit` best candidates.
- **Early exit exists and DOES terminate the producer**: `MatchCap` (exec/match_cap.rs:193; `DistinctLimitCap` mod.rs:23, `ordered_limit_cap` match_cap.rs:305, `plain_limit_cap` match_cap.rs:345) — the MATCH arm reads the RETURN/WITH suffix's DISTINCT/ORDER/LIMIT and stops the match walk once the suffix has enough (distinct) rows; `MatchCap::plain_want` (match_cap.rs:219) feeds the want into the chain (exec/match_clause.rs:185-212). At the scan level, the `cap` parameter chain — `Ask { cap }` (candidates/mod.rs:398) → `scan_ids` → `ExecGraph::lookup_nodes_upto(…, cap)` → `Graph::lookup_nodes_upto_at(labels, props, ts, cap: Option<usize>)` (index_lookup.rs:123) and `equality_postings_upto(…, cap)` — stops the store scan/walk at the first `cap + 1` matches (`RecheckWalk::visit` Break, index_lookup.rs:60-64).

**Verdict: suitable seam target.** Limit pushdown into a store scan attaches at the existing `cap: Option<usize>` parameter of `lookup_nodes_upto_at`/`equality_postings_upto` — the plumbing already reaches the store boundary; a columnar store scan honors the same cap (stop at cap+1 survivors). No new mechanism needed for plain LIMIT; ordered top-k pushdown into a scan is the one gap (the batch filter's zone maps note it as a deliberate future extension point — exec/batch.rs module doc).

## 6. Row and Value shapes

- `Row` — row.rs:116: `{ schema: Arc<RowSchema>, values: Vec<Value> }`. Two machine words + a Vec; schema is deduplicated per clause batch via Arc (schema charged once — `schema_ptr`/`schema_bytes`, row.rs:216/222). Walk binding appends values by `RowRung` stamping (row.rs:153) — O(values) per candidate, no name work.
- `Value` — relate-core/src/value/mod.rs:47, 14 variants: `Null, Bool(bool), Int(i64), Float(f64), String(Arc<str>), List(Arc<Vec<Value>>), Map(Arc<BTreeMap<String, Value>>), Node(Arc<Node>), Relationship(Arc<Relationship>), Path(Arc<Path>), Temporal(Temporal), Point(PointValue), Uuid(u128), Vector { coord, values: Arc<Vec<Value>> }, Bytes(Arc<[u8]>)`. Inline scalars; every composite payload is `Arc`-boxed and shared (`Value: Send + Sync`, ADR-0170) — a row-oriented baseline mimics it as a tagged enum of ~16-24 bytes with cheap clones.
- `Node` — value/mod.rs:24: `{ id: NodeId, labels: Arc<Vec<String>>, properties: Arc<PropertyMap> }`; `Relationship` adds start/end/type (mod.rs:31). `PropertyMap` — relate-core/src/value/props.rs:20: fitted sorted `Vec<(String, Value)>` (capacity power-of-two; replaced a BTreeMap to kill ~800B/node slack). `QueryResult` rows are `Vec<Vec<Value>>` (exec/mod.rs:247).

**Verdict: suitable as the baseline shape.** `Row`+`Value` are compact, Arc-deduplicated, and already the boundary representation everywhere; a row-oriented baseline store can adopt them verbatim. The columnar alternative should keep `Value` as the decode target (Chunk's `ColumnData` already shows the typed-buffer + Value-fallback encoding).
