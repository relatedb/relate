# Relate storage seams vs a Vortex property store — findings (2026-11-23)

Scope: the relate repository at main, read-only. Lab context: node-major table, row index == node id, per-key nullable columns, sorted (key,row) index side-file, immutable checkpoint files, mmap reads, WAL + live overlay.

## 1. VFS trait — verdict: FITS (with one caveat: no zero-copy read arm)

- Trait `Vfs` (relate/relate-storage/src/vfs/mod.rs:250) and `VfsFile` (:315), governed by **ADR-0072** (docs/adr/0072-virtual-filesystem.md, Decision §1–3 at lines 44–63). Backends today: `NativeVfs` (mod.rs:30, native.rs), `MemoryVfs` (mod.rs:26, memory.rs), `BundleVfs` (mod.rs:23, ADR-0074 single-file bundle), plus a wasm OPFS backend per ADR-0145. AGENTS.md:145/196 names Native + Memory as the persistence VFS pair.
- `Vfs` methods: `durable`, `create_dir_all`, `create_dir_all_for_atomic` (fail-closed default :255), `list_dir`, `exists` (fails closed), `metadata` (`VfsMeta`/`VfsEntryKind` :54/:87), `open(path, VfsOpen)` → `Box<dyn VfsFile>`, `open_exclusive`, `remove_file(s)`, `remove_dir_all`, `rename`, `sync_dir` (fail-closed default :299), `take_writer_lease`.
- `VfsFile` methods: `write_all`, `read_exact`, `seek`, `sync_all`, `durability_barrier` (ADR-0077, default :321), `set_len`, `len`, `stream_position`. All byte-copy I/O into caller buffers.
- **No mmap anywhere in the repo** (repo-wide grep for `mmap|memmap`: zero hits in code and Cargo.toml).
- A "mmap a vortex file" VFS: implementable **without changing the trait** — implement `Vfs`/`VfsFile` over mapped pages (`read_exact` copies out of the mapping; override `create_dir_all_for_atomic`/`sync_dir` since a durable VFS must, mod.rs:255/299; ADR-0072 §3 URI-selects-backend is the registration point). Caveat: `VfsFile` cannot hand out a borrowed `&[u8]`, so Vortex zero-copy decode would either mmap itself outside the VFS or need a new optional trait method (an extends, not a rewrite). WAL writes must stay synchronous through the same trait (ADR-0072 §1; ADR-0014).

## 2. Snapshot codec seam — verdict: FITS the multi-file/immutable/add-column shape; EXTENDS for columnar (non-row) export and per-column dirtiness

- Vocabulary: `SnapshotCodecKind` (relate/relate-storage/src/codec/kind.rs:12; Parquet/Json/Markdown/Rkyv), `ALL` table :39, `is_compiled`/`feature_name` (ADR-0105 optional codecs, feature-gated, fail-closed via `codec_unavailable` codec/mod.rs:115). **ADR-0050** (docs/adr/0050-snapshot-codecs.md, Decision §1–2 lines 40–51): "Codec owns store files", codec implements `load` (before WAL replay) and `dump` (checkpoint, after LSN pin); one codec per store, recorded in `manifest.json`.
- Behavioral surface: `CodecOps` fn table (relate/relate-storage/src/open.rs:30, `codec_ops()` :71): `finish_open`, `sweep_after_open`, `dump` (`CheckpointDump = fn(&StoreTarget, &dyn GraphImport, u64, u64, Option<&str>)` open.rs:15), `snapshot_data_bytes`, `has_published_snapshot` (ADR-0646 no-op skip). Loader is a generic match `load_with_checkpoint_lsn` (open.rs:131–138) over `SnapshotGraph` (relate-engine-api/src/export.rs:74, = `GraphImport + Default`).
- Codec resolution/evidence: `resolve_codec` + `read_envelope` (codec/mod.rs:290/:267) — a new codec must add an evidence row (`classic_evidence_at` :215 is compile-forced per `ALL`), plus layout facts `wal_dir`/`checkpoint_image`/`checkpoint_objects`/`engine_dir` (kind.rs:128/:143/:155/:170). Open-time knobs slot: `CodecOpenConfig` (codec/open_config.rs:18, ADR-0460) — "the next codec extends this enum"; it carried the Parquet wide variant until ADR-0553 deleted it.
- **"parquet-wide" is not a codec and no such flag value exists today.** ADR-0534 (docs/adr/0534-wide-column-parquet-shards.md) added wide-column parts *inside* the Parquet codec — explicitly rejected a new `SnapshotCodecKind` (its Alternatives, line 121) — one typed column per promoted key + residual tagged-JSON column, immutable per-part files, add-column at re-encode, carried columns copied forward (lines 57–97). ADR-0553 (docs/adr/0553-wide-columns-are-the-parquet-checkpoint-format.md, lines 37–39, 81–82) made wide the *only* Parquet write encoding and deleted the opt-in CLI value; `--snapshot-format` parses only `SnapshotCodecKind` (surfaces/relate-cli/src/flags/snapshot_format.rs:10; ADR-0163). So the precedent for Vortex is ADR-0534's shape: column files inside a codec, not a new flag.
- **Sufficiency for a Vortex checkpoint**: NOT hardwired to single artifacts — the Parquet codec already publishes many immutable files (id-window shard parts, per-column leaf files, manifest; ADR-0022, ADR-0089 immutable checkpoint shard publication with `sweep_orphans`), already adds columns at checkpoint (wide schema re-derivation, ADR-0534), and the manifest version selects encoding. Two real gaps: (a) `dump` receives the graph only through `GraphImport` (export.rs:39) — row/materialized access (`node_at`, `dirty_node_ids`), so a Vortex writer that wants to encode columns without materializing rows needs a `GraphImport` extension or its own store-side handle; (b) `CheckpointDump` is a bare fn pointer, fine for parity with the others. A `SnapshotCodecKind::Vortex` variant is additive: one `ALL` row, one `CodecOps` row, one evidence row, one loader arm.

## 3. Property store read path — verdict: NEW SEAM NEEDED (fully concrete today)

- Live record: `LiveNode { labels: Vec<u32>, props: CompactProps }` (relate-executor/src/store.rs:83). `CompactProps` is **pub(crate)** and concrete: `{ keys: Vec<u32>, vals: Vec<Value> }` (relate-executor/src/store/compact_props.rs:14) — ADR-0033 (docs/adr/0033-compact-live-records-typed-csr.md, Decision §1–2 lines 41–47: interned keys, compact property list per version, materialize public maps at the API boundary).
- Executor point read: `Graph::node_prop_id_at` (relate-executor/src/graph/prop_read.rs:8) → `self.nodes.get(&id)` (MVCC version chain) → `visible_version(&vers, ts)` → `v.live.prop_by_id(kid)` (store.rs:153). Token-resolved entry: `node_prop_resolved` (relate-executor/src/overlay/reads.rs:256, ADR-0541 plan tokens; `prop_key_id_resolved` :245). Callers: pattern_walk/admit.rs:166, exec/candidates/mod.rs:493, exec/batch.rs:350, exec/kernels/{chain.rs:401, hub_star.rs:523, program.rs:246}. There is **no trait between executor and property storage** — `Graph` (relate-executor/src/graph/mod.rs) is the concrete store; the only abstraction is `SnapshotGraph`/`GraphImport` at *load/checkpoint* time, and the write overlay (ADR-0016, docs/adr/0016-write-overlay.md — private `WriteScratch` overlay over the live graph, reads overlay-first).
- What must become a seam for O1 point reads / O4 filters: (1) the `base: Graph` field the overlay views read through (overlay/reads.rs) — introduce a property-read trait at the `node_prop_id_at`/`rel_prop_id_at`/label-and-scan-predicate boundary; (2) the restore path (graph/restore.rs) that installs `LiveNode`s directly from codec rows; (3) the lazy equality postings and label buckets (ADR-0614, docs/adr/0614-equality-match-lazy-postings-serve.md — postings are identity buckets of interned (label,key) built by walking live nodes, Decision §1 lines 44–56; a Vortex sorted (key,row) side-file is a natural replacement for exactly these); (4) the ADR-0042 charge walk (graph/accounting.rs) that counts live versions. Layout ADRs: ADR-0033 (compact records), ADR-0016 (overlay), ADR-0013 (tuple MVCC), ADR-0541 (token reads), ADR-0614 + ADR-0063/0010/0040 (indexes/postings), ADR-0042 (memory).

## 4. Checkpoint / seal lifecycle — verdict: FITS for immutable multi-file publication; per-column compaction EXTENDS the codec's unit planner + GraphImport's dirty set

- Write path: facade `relate/src/checkpoint.rs` — `Publication` lock (`begin_publication` :27, `begin_reload_swap` :36), `run_checkpoint` :123 with `Trigger` (timed/close/explicit; ADR-0041 timed, ADR-0646 no-op skip), WAL rotate + LSN pin, then `relate-storage` `checkpoint_at` (relate-storage/src/lib.rs:732) → `CodecOps.dump` (open.rs:34). Parquet: `checkpoint_at_with_bytes` (snapshot/native/mod.rs:180), per-kind rewrite seeded from `graph.dirty_node_ids()/dirty_rel_ids()` (mod.rs:569; `Kind::dirty_ids` :58), `coalesce::rewrite` rewrites only units touching dirty ids, clean parts byte-stable (snapshot/native/coalesce.rs; ADR-0022 id-window shards, ADR-0183 coalescing). Immutable publication + orphan retirement: `sweep_orphans` (ADR-0089).
- Reload: open = load snapshot → `Wal::open` at checkpoint LSN → replay validated records (open.rs:198 `open_store`; ADR-0014) → codec `finish_open`/`sweep_after_open`. Follow mode: `relate/src/follow.rs` (`poll_follow`, `catch_up`, reload swap replacing the graph under pins); markdown codec's deferred re-baseline is the one existing deferred open action (open.rs:171).
- Per-column compaction (rewrite only changed column files): the natural home is the codec's unit planner (`coalesce.rs` `plan_units`/`source`), which already copies unchanged rows/columns forward byte-for-byte (`previous_shard_columns`, codec/parquet/copy.rs; ADR-0534: "copied rows are re-read, not re-derived"). What's missing: dirtiness is exported only as **ids** (`GraphImport::dirty_node_ids/dirty_rel_ids`, export.rs:18–19), never per-key — so "only key k changed on these rows" is invisible to a codec. Either extend `GraphImport` with per-key dirty stats or maintain codec-side continuous per-key statistics, which ADR-0534 already records as the follow-up direction (docs/adr/0534-wide-column-parquet-shards.md, Consequences lines 141–144, and the tiered-arena future at 154–158: "checkpoints become stable files plus appended delta files with periodic compaction"). ADR-0635/0655 (seal floor) are the in-memory adjacency-delta-tier analog (ADR-0551/0608): the checkpoint fold pass notes per-chunk stability and seals stable chunks — the same "note at pass N, act at pass N+1" pattern a per-column compaction would reuse at checkpoint time.

## 5. Memory metering — verdict: EXTENDS (a new accounting decision for mmap pages)

- `WorkspaceCharge` (relate-core/src/tokens.rs:320): reservation for one owned *workspace* (query-time) structure — `retain/resize/retain_with/resize_with/transfer_to_ledger`, enforced through the thread-local `TokenLedger` (ADR-0463 expression allocation budget, ADR-0499 per-row fold charge). `RetainedTotal` (relate-executor/src/overlay/budget.rs:269): one retaining container's running total (ADR-0463), grown via `add_bytes/add_row/add_rows` against `ExecGraph`.
- Store memory is a different meter: **ADR-0042** (docs/adr/adr 0042-graph-memory-limit.md, Decision lines 49–79) — a *logical* cap on live customer data: `Value::logical_bytes` (relate-core/src/value/mod.rs:216) + fixed overheads, maintained by graph/accounting.rs (`used_bytes`, `recompute_used`, `estimate_redo_delta`); postings charged since ADR-0172/0614; explicitly **out of budget**: WAL, Parquet/object-store buffers, overlay and query scratch (lines 57–60). Context (lines 36–39): "Process RSS is the wrong meter."
- Mmap'd file memory counts **nowhere** today: no mmap exists, and the budget is logical bytes, not resident pages. A Vortex mmap store would interact with: (a) the ADR-0042 `used` counter for logical data size — the natural place to charge an `UncompressedSizeInBytes`-style figure so the customer-data ceiling still means something; (b) `WorkspaceCharge`/`RetainedTotal` only for query-produced containers, never for the store itself; (c) nothing for page-cache residency — whether mmap resident pages count toward any cap is an open decision ADR-0042 does not answer (its "Parquet buffers out of budget" precedent suggests out, but the mmap store *is* the live store, so this needs its own ADR).

## Summary table

| Seam | Fits today | What's missing |
|---|---|---|
| VFS (ADR-0072) | Yes — new backend = new `Vfs` impl, no trait change; `VfsFile` is byte-copy so an mmap backend works | No borrowed-slice/zero-copy arm; Vortex zero-copy decode must mmap itself or the trait gains one optional method |
| Snapshot codec (ADR-0050/0105/0534/0553) | Yes for many-file immutable checkpoints with add-column-at-checkpoint (Parquet already does exactly this); new `SnapshotCodecKind` + `CodecOps` + evidence row is additive | `dump` sees the graph only as `GraphImport` rows; per-key dirtiness not exported (ids only); `CodecOpenConfig` extension for knobs |
| Property read path (ADR-0033/0016/0614) | No — `CompactProps` (pub(crate)) inside `LiveNode` inside `Graph` version chains; zero traits between executor and storage | A property-store trait at `node_prop_id_at`/scan-predicate boundary; overlay `base` indirection; restore path; postings (0614) swap for the sorted (key,row) side-file; ADR-0042 charge walk |
| Checkpoint lifecycle (ADR-0012/0014/0022/0089/0183) | Yes — immutable shard publication, dirty-id incremental rewrite, orphan sweep, follow reload all exist | Per-key dirty tracking (GraphImport or codec-side stats per ADR-0534 follow-up) for per-column compaction; stability-seal pattern (ADR-0635) as the model |
| Memory metering (ADR-0042/0463) | Partially — logical-bytes counter is the right hook for an UncompressedSizeInBytes-style charge | Mmap resident-page accounting is undecided/absent; needs its own ADR; `WorkspaceCharge`/`RetainedTotal` are query-scratch only, not store meters |

## Suggested order (from the research)

1. Property-read trait (biggest, unlocks O1/O4)
2. `GraphImport` per-key stats (per-column compaction)
3. mmap-accounting ADR

## Decision note (2026-11-23, after the research)

The layout decision landed after this research was written: **row-range
shards, not per-column files** — the per-column option this document
analyzed (and the per-key dirty-statistics extension §4 describes as its
input) is rejected. With column-complete struct files per node-id window
(ADR-0022's shape), the dirty-node ids `GraphImport` already exports are
sufficient for incremental compaction, and the codec-seam extension list
shrinks to one item: the columnar (non-row) export path for `dump`.
